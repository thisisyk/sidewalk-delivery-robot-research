# 人行道配送机器人：移动行人与独立求助机制

当前主界面使用人行道配送机器人。**机器人和行人只在人行道与斑马线通行，全部汽车（包括停车）只在机动车道。** 行人有实际随时间变化的坐标；默认从人群场景首帧播放，可以暂停、重播、拖动时间或调整速度，不自动跳到协助或到达时刻。

## 本轮修复与实验问题

旧版把协助请求完全绑在近距模型的有效高分上。机器人已进入两米近距范围后，原任务资格无效，分数显示“—”；即使持续受阻也无法请求。协助后的重规划又依赖先提出请求，于是出现“无法评分→不请求→不重规划→继续堵塞”的闭环。空闲席位不能主动接到尚未进入队列的机器人。

**本轮增加独立的行为求助通道：持续停滞、机器人互堵或多次路径规划失败，可以不依赖模型分数提出请求。** 模型的高分通道保留，几何约束和协助服务流程保留；同一请求记录原因。新增通道是人工设定的工程策略，不是模型从Waymo数据中学会了识别故障或解卡。

本轮还把协助员处理改为显式的规则模块，记录指令与执行结果。因此主对照衡量的是“行为求助＋显式协助处理”的组合机制，不能把全部变化归因于请求触发或机器学习。若输出包含仅开启行为求助的消融，单独列出，避免混合归因。

本轮问题是：在完全相同的场景、种子、人流、机器人和服务资源下，新增机制能否修复“受阻却不请求”，它又带来多少请求、等待或接触变化？不预设所有机器人都会到达。

## 触发条件与工程假设

原模型仍只接受过去约一秒观测，以同一194列特征和原开发集阈值0.95568571118795评分。当前已进入两米事件范围仍显示不评分；没有把无效分数改成高分来制造请求。模型门控通道仍要求至少两秒受阻。

独立触发的实际配置记录如下，秒数、次数、冷却和重试上限均为本模拟的工程假设，没有用真实接管标签估计：

```json
{
  "persistent_stall_s": 5.0,
  "stationary_robot_blockage_s": 2.0,
  "consecutive_planning_failures": 2,
  "retry_cooldown_after_service_s": 15.0,
  "max_requests_per_robot": 3,
  "waiting_queue_slots_per_operator": 2,
  "minimum_fleet_request_interval_s": 0.5
}
```

协助采用先到先服务、每次15秒的简化假设。请求不等于已经获助，更不等于一定解困；队列积压、不可行路径和再次受阻均应保留。重规划只能使用当前已知静态障碍和许可步道/斑马线，不能为提高完成数穿越机动车道。

## 人工协助模块与机器人执行

`assistance.py`中的协助员是规则模拟器，没有真人远程操控或语言模型驾驶。机器人先提交原因和当时可观察状态，FIFO分配席位；服务完成后给出明确指令，机器人再按指令执行并记录反馈。协助方案记录如下：

```json
{
  "module_version": "sidewalk_operator_v2_visible_robot_blockers",
  "enabled": true,
  "decision_source": "scenario_rules_or_user_selected_simulation_command",
  "actions": {
    "replan_walkway": "批准步道内重新规划",
    "hold_then_resume": "暂停让行后重新检查",
    "onsite_required": "保持停车并升级现场处理"
  },
  "hold_s": 3.0,
  "review_radius_m": 4.0,
  "onsite_arrival_simulated": false,
  "motion_guard_override": false,
  "planning_failure_does_not_prove_real_world_has_no_route": true
}
```

- `replan_walkway`：在已知障碍与许可通行域内给出新路线；本版还把**当前可见、速度小于0.05米/秒的其他机器人完整占地**作为临时规划障碍，绕开实际互堵位置，而不是再次批准穿过它的原路线。机器人安装路点后再由原几何约束逐步实走。保守规划器失败只表示没有找到可接受路径，不证明现实中必然无路。
- `hold_then_resume`：对暂时性的动态阻挡先保持3秒，再按规则尝试恢复；不允许直接穿过行人或机器人。
- `onsite_required`：没有可执行绕行方案时标记需要现场处理并保持停止，不伪造远程已经移除了垃圾、建筑或其他机器人。

临时阻挡只使用此次审查时已观测到的静止机器人，不把移动或隐藏机器人冻结成已知地图障碍。规划后仍保留原逐步避障与通行域检查；静止目标之后可能移动，因此静态快照不等于未来通道保证。

自动选择规则只看当前可见目标：4米内有移动行人且没有机器人阻挡时，优先短时让行；其余情况尝试许可区域内重规划。4米观察范围和3秒让行都只是显式工程假设。用户选择操作办法也不能授权越过步道边界或关闭避障。

这些是离散的简化操作办法，不包含真实遥控、物体搬移或全面互相避让。获助后仍可能受阻，需查看后续运行、重试与最终状态，不能仅凭“协助结束”宣称成功。独立的[协助生命周期审计](../results/sidewalk/assistance_audit.json)核对保存的请求原因、时序、资源约束、指令与实际运动，不导入模拟控制器。

## 实际人工协助案例：人群场景

本例固定选择人群场景最早发出的请求，不按是否成功筛选。这里的“人工”指规则模拟协助员；没有真人远程控制。

机器人ID为 `0`，请求 `robot_0_request_1`，原因 `robot_blockage`；请求时模型资格为 `False`、评分为无有效分数。

| 环节 | 实际时间或值 |
| --- | --- |
| 提交请求 | 48.60秒 |
| 席位开始处理 | 48.60秒 |
| 完成审查/下发指令 | 63.60秒 |
| 下发动作 | `replan_walkway` |
| 指令来源 | `scenario_rules` |
| 本请求最后执行状态 | `completed` |

实际下发的操作步骤：

1. 下发新的步道/斑马线路点
2. 按原速度上限与逐步通行检查执行
3. 若再次受阻，记录停滞并按冷却和次数限制重新请求

处理器当时的说明：根据已知建筑、已发现障碍及2台当前可见静止机器人的占地生成步道新路线。动态对象仍逐步触发避让。

实际下发的路点（米，来自保存的指令；不重新生成路线）：

```json
[[58.48600126848153, 44.5], [59.0, 44.0], [95.0, 44.5]]
```

执行反馈按保存时间顺序列出：

| 时间/秒 | 状态 | 实际记录 |
| ---: | --- | --- |
| 48.60 | `queued` | 协助请求进入FIFO队列 |
| 48.60 | `reviewing` | 模拟协助员占用席位，检查当前观测与已知地图 |
| 63.60 | `route_executing` | 已下发新路点；机器人按原通行约束执行 |
| 93.00 | `completed` | 机器人实际到达任务终点 |

在本指令下发前最后保存帧63.50秒至下一次请求前/模拟结束的120.00秒之间，控制器累计的指令后行程增加 **36.7130米**，保存位置的净位移为 **36.5140米**。行程计数来自每0.1秒实际运动更新；窗口端点为0.5秒保存帧，不把路线下发或状态名称当作位移证据。

截至120.00秒，该机器人任务终态为 `done`，`done=True`，位置为(95.000, 44.500)米；该机器人在本轮共请求1次协助。已下发指令后的累计实际行程为36.713米。

`route_executing`表示路线已下发并进入执行尝试，单凭该状态不能证明脱困。是否实际移动、是否到达终点，分别由行程计数/保存坐标与 `done` 判断；若指令后继续受阻两秒，会记录 `blocked_after_instruction`，若重试则原请求记为 `replaced_by_retry`。失败不改写为协助成功。

改动后，请求通道和任务完成要分别判断。若独立行为请求成功进入队列，只说明这条请求不再依赖模型资格；完成数、等待和接触的变化才说明后续简化协助规则产生了什么结果。**即便请求恢复，也不能据此声称所有死锁已解决、接触减少或模型预测变准。** 仍未完成的任务、接触帧和规划失败按输出保留。

## 与其他规则策略的关系

保存的每个主回放同时包含旧纯模型门控、等待两秒即请求、仅自主等待的汇总（`policies`）。这些策略用于机制对照，不能把新策略相对旧策略的变化全部归因于模型。请求次数也不能直接换算为人工时或每单成本；本模拟没有现实操作员效率数据。

## 真实模型与规则的分工及结论边界

分数仍由原开发集选择的全特征HistGradientBoosting产生，输入为同一194列过去轨迹特征。重训只使用原857个训练样本；原206例预测一致性记录保留。该模型来自道路车辆训练域，**没有训练过本次人行道配送机器人**，分数未在该域校准。其他机器人以车辆运动代理编码用于兼容特征，不代表模型已经学会机器人语义。建筑、垃圾与围挡没有被伪装成车辆。

通行域约束、避让、路线跟随、栅格A*、独立行为求助、显式协助指令、15秒服务和排队均属于简化工程规则。外生行人和车辆采用脚本运动，没有全面双向反应、车辆动力学、传感误差或完整交通规则。结果只能说明这些规则在固定合成场景里的作用，不能证明真实配送接管率、安全性、模型性能或成本改善。

本轮保留了原道路研究结果，没有新增真实评估样本、改标签、重新选模或宣称AP变化。它补足的是“无效模型分数时仍能发起行为求助”的系统逻辑；后续还需要独立机器人轨迹、停滞/接管标签及真实闭环验证。
