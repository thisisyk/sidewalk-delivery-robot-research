# 研究局限与结论边界

真实 WOMD 实验已完成。本次8,910个原始场景中，6,383个（71.64%）因未来轨迹不完整而删失；主评估集206例、33个正例、5个分片。完整结果见[最终报告](final_report_zh.md)。本文件界定这些结果不能支持的主张。

## 与文章及 Uber Eats 的关系

文章提出配送机器人会因障碍、保守安全策略或远程协助而停止，并关注人工介入与运营效率。本文借此研究“复杂交互如何被提前筛出”的一个可测子问题。

[Uber 的合作公告](https://www.uber.com/us/en/newsroom/uber-and-waymo-autonomous-deliveries-phoenix/)证明 Waymo 曾为 Uber Eats 开展自动配送；它不能证明 WOMD 中任何一个场景正在执行外卖订单。本项目数据不含已确认的订单状态、配送费用、远程操作时长或接管理由。

WOMD 是道路汽车数据。人行道小车在尺寸、速度、法规、感知范围和人群交互上不同；结果不能直接外推至截图中的 Serve Robotics 车辆。

## 代理标签与因果边界

- 近距离交互可能是正常并行、低速通过或礼让，不能直接称为危险、事故或自动驾驶失败。
- 停止与低速也不能自动解释为算法卡住。
- 离线风险分数无法说明请求人工后会发生什么。它不能证明降低事故、减少延误、降低人工接管率或改善每单成本。
- 所谓人工复核预算只是离线排名容量，不含操作员服务时长、同时管理车辆数、网络延迟或排队模型。
- 数据并未为本实验提供真实人工协助需求标签，因此不应把预测正例称为“真实需要接管”。

## 数据生成与删失

官方说明 WOMD 包含人工驾驶与自动驾驶模式的未标注混合。不能用本数据推算纯无人驾驶车队的失败率。[官方数据说明](https://waymo.com/intl/en-ca/open/data/motion/)

当前未被观测、五十米范围外或筛选上限以外的对象不在本任务定义内。未来缺失时进行删失，可能更常排除遮挡、出视野和复杂交互；完整测量子集的效果未必代表所有道路场景。必须报告删失比例，不能把低删失后错误率理解成总体安全性。

当前已在近距离阈值内的场景被排除，结果仅针对新进入阈值的事件。不同阈值的保留队列可能不同，不能把敏感性表误读为同一队列上的直接优劣比较。

二维旋转矩形及离散时间采样近似会产生几何误差；地图中的高低差、复杂车身形状与极短事件没有完整建模。标注轨迹本身也存在测量误差。

## 相关性、样本量与泛化

官方 train/validation 边界优于行级随机拆分，但内部 shard 分组并非已验证的原始驾驶日志分组。重叠窗口与同地点反复经过可能导致相关性；自举区间取决于所用抽样单位，不能保证完整覆盖该相关性。

一个真实数据 shard 可以支持流程验证，不能自动支持跨城市、全天候或商业部署的结论。正例少时 AP、召回率和子组差值可能波动很大。应报告全部样本与正例数，区分流程试运行、探索性发现和有足够证据的比较。

初始实验只比较简单 CPU 模型与恒速基线，不能宣称超过所有深度学习方法或达到最先进水平。若无地图输入，不得把结果描述为地图融合的贡献。

## 可接受的最终结论形式

真实实验完成后可写：“在所列 WOMD 子集与本研究定义的三秒近距离代理事件上，模型 A 在固定复核预算下取得了 X 的召回率，与恒速基线相差 Y；区间为 Z。结果支持／尚不足以支持利用学习模型改善离线复核排序。”

`X/Y/Z` 只能来自实际保存的评估输出。结论还须注明所用数据规模、阈值、筛选规则和不能推断真实配送接管效果的原因。不能为了得到“优秀”结论反复挑选测试结果、隐藏负结果或生成虚构数字。
